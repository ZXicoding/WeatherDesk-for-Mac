# 天气桌面 for Mac

把**当地实时天气**画到桌面背景上：外面下雨，桌面就落雨；外面下雪，桌面就飘雪；到日落时分，桌面就是一片晚霞。macOS 原生 Swift + AppKit，纯本地渲染，不依赖 Electron，不需要 API Key。

![形态](https://img.shields.io/badge/macOS-13%2B-blue) ![语言](https://img.shields.io/badge/Swift-5-orange) ![许可](https://img.shields.io/badge/license-MIT-green)

## 它是怎么做到「实时同步」的

```
Open-Meteo 实时天气 ──┐
IP / 系统 / 手动定位 ─┼→ 天气状态 + 当地日出日落 → 天空渐变 / 日或月 / 云 / 雨雪 / 雾 / 雷电
本机时钟（每 20 秒） ─┘                              ↓
                                        每块屏幕一块桌面级透明窗口
```

- **天气**：每 10 分钟（可设 5 / 10 / 30 分钟）拉取一次当地实况：温度、体感、湿度、风速风向、降水、云量、WMO 天气码。系统唤醒时立刻补一次，断网时保留上一帧画面并自动重试。
- **昼夜与天体**：接口返回的是**当地**日出 / 日落时刻（不是「是否白天」这个布尔值），用于判定相位；太阳、月亮、行星与恒星的位置则由本机时间 + 经纬度按天文算法实时计算，每 20 秒推进一次。日落是平滑过渡，星图也会随恒星时缓慢西移，不会到点突变。
- **位置**：默认用 IP 自动定位（不弹权限框）；菜单栏可切换到系统精确定位（会请求定位授权）或手动搜索城市。定位成功后缓存，下次断网也能用。
- **渲染**：画面不是一张渐变贴图，而是分层合成的光照结果：
  - **形状**：云和雾用分形噪声（value noise + fBm）烘焙成透明遮罩，雨丝带运动拖影，雪花有亮核与六角辐条，月面有球面明暗与月海暗斑。这些纹理在进程启动时算一次并全局共享，运行时不占 CPU。
  - **光照**：五段天空渐变 + 地平线辉光 + 跟随太阳的大气散射 + 云顶亮云底暗 + 镜头暗角。日轮在日出日落变大、转橙红并被大气折射压扁；月亮按真实月相显示，新月只留极淡的地球反照。
  - **景深**：云、雨、雪各分远 / 中 / 近三层，尺寸、速度、透明度、摆幅都不同；每个个体的速度、相位、摆幅还带随机扰动，不会出现整排粒子齐步走。阴天另铺一层大尺度低对比层云幕。
  - **合成**：全部是 `CALayer` + `CAAnimation`，由 GPU 合成。窗口在桌面壁纸层、`ignoresMouseEvents = true`、随所有 Space 显示，不挡图标、不抢焦点、不出现在 Dock 或 Mission Control。
  - 雨雪用显式粒子图层而非 `CAEmitterLayer`——后者在发射线贴近图层边界时会被系统整体剔除，导致雨雪从屏幕顶部落不下来。

## 夜空是真的：星星按当天、当地排布

夜里的星点不是随机撒的装饰。App 内置 **8912 颗肉眼可见恒星**（依巴谷 / Yale BSC，J2000 赤经赤纬、视星等、B-V 色指数）与 **88 个 IAU 星座的 692 条连线**，运行时完全离线：

- 由本机时间算儒略日、格林尼治平恒星时与本地恒星时，把星表从 J2000 做岁差改正到今天；
- 用定位得到的经纬度，把每颗星的赤道坐标换算成此刻的高度角 / 方位角，再加大气折射与 Kasten–Young 大气消光（低空星变暗、变红）；
- **太阳、月亮、五颗行星和所有恒星共用同一套坐标与同一个立体投影**（朝南窗口、142° 视场），所以「金星就在那几颗星旁边」是真的在同一方向；
- 月相、月光、暮光与云量共同决定当晚的极限星等：满月夜只剩几十颗亮星，无月晴夜能看到几百颗；月亮没升起就不会挂一个假月亮；
- 星等决定大小与亮度，B-V 决定色温；亮星有衍射星芒与视宁度闪烁，行星稳定不眨眼；银河沿银道面铺雾斑，偶发流星划过；日出前 / 日落后 18° 曙暮光连续过渡，地平线还有一层随云量变化的城市光害。

右下角角标会写出「今夜可见：宝瓶座 · 鲸鱼座」这类**当夜真实可见**的星座。菜单栏「显示星座连线与星名」可打开极淡的连线与中文亮星名来核对星图，默认关闭——真实天空里没有线。

星表原始数据来自 [HYG Database](https://github.com/astronexus/HYG-Database) 与 [Stellarium modern skyculture](https://github.com/Stellarium/stellarium)，由 `tools/gen_catalog.py` 离线压成 `Sources/StarCatalog.swift`。

## 天气 → 画面对照

| 当地天气 | 桌面表现 |
| --- | --- |
| 晴 | 通透蓝天、太阳按真实天文高度连续划过；夜里是按经纬度与恒星时算出的真实星图（含银河、行星、月相与当月可见星座） |
| 少云 / 多云 / 阴 | 按实时云量生成噪声云，三层视差漂移、边缘缓慢翻卷；阴天再叠一整片低对比层云幕 |
| 毛毛雨 / 下雨 / 大雨 | 三层景深的斜向雨丝：近处长粗快、远处细短慢，随风倾斜，落地有溅水与雨雾 |
| 雷阵雨 | 大雨 + 随机分叉闪电（锐利折线 + 辉光）与双闪，天空压暗、层云翻涌 |
| 下雪 / 雨夹雪 | 三层大小不同的雪花，各自飘摆、缓慢旋转，天空转冷白、地面有积雪反光 |
| 雾 | 灰白天空 + 全屏雾幕压低对比 + 三层噪声雾带缓慢流动 |
| 日出 / 日落 | 橙红晚霞、日轮贴近地平线并变大转红、地平线暖光把云染成暖色；**这些过渡由本机实时推算的太阳真实高度驱动，日落那一刻画面就切换，不等待下次联网** |

右下角有一张半透明天气角标，显示城市、温度、天气、体感、风、湿度、云量；**白天直接显示当天日出 / 日落 / 月升的本机实时时刻，夜里还会显示当夜可见星座、画面里真实恒星的数量与月相（标注「实时」）**。可在菜单栏关掉。菜单里另有「下一次日出 / 日落 HH:mm（约 X 小时 Y 分）」倒计时。

## 使用

双击 `天气桌面.app` 即可。它是菜单栏应用（不显示 Dock 图标），菜单栏右侧会出现一个天气图标和温度。

## 开机不黑屏（v1.1 起）

登录项在开机时抢跑，Wi-Fi / DNS 与 WindowServer 常常还没就绪：旧版会建好桌面窗口却拿不到天气数据，也不重试，于是桌面变成一整块黑。v1.1 加了四道保障，开机瞬间就有画面：

| 保障 | 做法 |
| --- | --- |
| 离线首帧 | 最近一次成功的天气完整缓存进 UserDefaults；启动后**不等网络**，立刻用它渲染桌面。全新安装则按本地天文时刻生成一个合理天空，绝不空窗 |
| 请求不死锁 | 每次请求带 15 秒 watchdog，定位/网络回调丢失时强制解锁 `busy`；失败后 5→10→20→40→60 秒指数退避重试，网络一恢复立刻回到实时数据 |
| 首次联网延后 | 开机 2 秒后才发第一个请求，避开系统网络栈初始化窗口 |
| 桌面层重绘 | 启动后 2s / 8s 各重绘一次；3s 时若仍无任何天气帧，主动补一帧离线画面，覆盖 WindowServer 早期未合成的情况 |

调试时可完全断网复现开机场景（不发任何请求）：

```bash
"/Applications/天气桌面.app/Contents/MacOS/WeatherDesk" --simulate-offline
```

## 背景来源（2 小时档位底图 v1.5.0 / 实时摄像头 v1.4.0）

默认是「**实景照片 + 粒子效果**」：用一张照片级实景做底图，云、雨丝、雪花、雾幕、闪电与流星全部作为半透明动画层叠在照片上，所以背景是真实场景，但依然是「活」的。照片自带光照，程序化天空渐变、日月与星图在照片模式下让位；切到「程序化天空」即可回到纯分层光照画面。

**底图按当地挂钟每 2 小时换一张（v1.5.0）**：一天切成 `00 / 02 / 04 … 22` 共 12 档，内置 `scene-h00.jpg … scene-h22.jpg`。以前只分白天 / 日出日落 / 夜三档，日落后到次日日出前（冬季华北约 14 小时）一直挂着同一张夜景，下午和深夜看起来完全一样；现在深夜是深蓝暗调、午后是明亮暖调，一眼可辨。档位用的是 IP 定位返回的**当地时区**（Open-Meteo `timezone=auto`），换到跨时区的城市会按新挂钟对齐；`Sources/SceneClock.swift` 是纯函数，偶数整点边界由 `DesktopController` 单独排一次定时器，机器睡醒也会立即按当前时刻重选，不等下一次天气刷新。

天气仍由粒子层表达：雨丝、雪花、雾幕、闪电照常叠加在该档底图上；也可以在目录里放 `scene-h00-rain.jpg` 这样的文件，让某一档在雨雪天优先用另一张图。关掉菜单栏「背景来源 → 每 2 小时更换底图」即回到旧的 `scene-clear / sunset / night / rain / snow` 五张，旧的 5 张同时也是 12 档素材缺失时的兜底链。内置的 12 张由上述已确认的 4 张开阔湿地实景照片做**离线确定性光照分级**（轮换构图、曝光、色温、天光渐变）而成，不是 AI 生成、不拼接、运行时只读 JPEG 文件，不下载也不计算图片；逐档来源与许可见 `Resources/图片来源.txt`。

内置照片（v1.3.4 起）按**所在地生态 + 开阔视野**挑选：天津静海属于海河下游冲积平原，本地该是芦苇荡、浅水湖沼、草甸与冬季冰面，而不是白桦林、热带云雾林或雪松林。五张统一换成**低平地平线 + 大面积天空 + 开阔水面／草甸／雪原**的构图——不再有窄水沟、两排树夹着一条小河，也不再有芦苇、香蒲怼在镜头前的近景特写。其中 `scene-clear.jpg` 是中国华北的开阔绿苇草甸，`scene-sunset.jpg` 是河北衡水湖的暮色大水面；夜／雨雾／雪三张取自荷兰、芬兰、波兰的平原浅湖与冰面，视觉上是同一类湿地生态，拍摄地已在 `图片来源.txt` 逐张如实标注，没有冒充天津。v1.3.3 那张 Commons 明确标注「Jinghai, Tianjin, China」的静海本地实拍，因为构图是窄水道，按本版要求撤下。画面里依然不含建筑、道路、路灯、栅栏、车辆、人物、渔具或农田设施，也不取银河、完美镜面倒影、巨大落日、雪山金光这类「一看就像屏保」的风光大片；个别照片为保持纯自然与开阔，裁切时去掉了近景树枝、岸边设施与远处地平线杂物。

**这不是「每换一个 IP 就自动换当地实拍」**：联网取图会被网络与版权卡住，运行时拼合图片又会让没准备过的城市露馅。所以这套是本地固定素材，按生态贴近所在地；每张的实际拍摄地、作者与许可都如实写在 `Resources/图片来源.txt`，没有把外地说成天津。要给某个城市用真正的当地照片，用下面的地点专属照片包。

想让不同地点显示不同实景，用地点专属照片包（无需重启，放进照片后下次重绘即生效）。
选图顺序是「先找齐 12 档，再退回旧命名」，跨所有目录层级：

1. `~/Library/Application Support/天气桌面/scenes/<区域-城市>/`，目录名依次尝试 `区域-城市` / `城市` / `区域`
2. 生态带照片包 `Contents/Resources/biomes/<pack>/`（开启「按生态带自动切换背景」时）
3. `scenes/default/`
4. App 内置的 `Resources/photos/`

每一层先按当前档位找 `scene-hHH-rain.jpg`（雨雪）/ `scene-hHH.jpg`；12 档都没命中，才退回旧的 `scene-clear / sunset / night / rain / snow.jpg`。放一张就只覆盖那一档，不必凑齐 12 张。替换 `Resources/photos/` 下的图可改内置兜底（v1.3.4 起内置图与 `scenes/default/` 已同步换成开阔视野的平原湿地景观，并统一裁成 1536×924）。缓存 key 带「目录 + 图名 + 档位」，换地点、跨偶数整点、改设置、插显示器都会重新选图；网络切换（换 Wi-Fi / 开 VPN）触发 `NWPathMonitor` 立即重新定位，不必等下一次轮询。开机断网时用上次缓存天气照样出画，不会黑屏。

菜单里还有两个**可选**来源：「程序化天空（无底图）」回到最初的纯分层天空；「当地生态绘制（实验）」按经纬度现场画山脊与植被，是分层绘制而非照片，`Sources/EcoScene.swift` 独立实现，默认不启用。切换来源时会清底图缓存并重建全部动画层，不会留下旧粒子。

### 实时摄像头（v1.4.0，可选，默认关闭）

菜单栏「实时摄像头 → 启用公开实时摄像头」打开后，底图换成**当前 IP 所在地附近一台公开 Web Cam 的最新画面**。这把「换 IP 就换当地风格」做成了真事：`Sources/LiveCamCatalog.swift` 内置 689 个带经纬度、名称与归属地区的公开摄像头索引，按大圆距离挑最近的几个（山景 / 海岸 / 湖泊等自然机位给一点优先）；换 Wi-Fi、开 VPN、换出口 IP 触发 `NWPathMonitor` 立即重新定位，`DesktopController.consume()` 发现地点变化就切换摄像头、清掉旧地点那一帧，抓到新帧才替换底图。菜单里也能手动固定任意一个附近摄像头。

取的不是连续视频流，而是这些摄像头**每十几秒刷新一次的 JPEG 实时帧**（`opencam.live/api/cctv/frame/<id>`）。默认每 20 秒拉一张（可设 15 秒～2 分钟），一张约 20–200 KB：不长期解码视频、CPU 几乎为零，直接复用现有底图图层，云 / 雨 / 雪 / 雾粒子层照常叠加。最近一帧缓存在 `~/Library/Application Support/天气桌面/livecam/last.jpg`，开机先用旧帧；取帧失败会依次尝试附近其他候选，全部失败就**自动回退静态照片**、60 秒后重试，不会黑屏。

**为什么默认关闭**：真实摄像头不比精挑的底图——夜间多为暗场城市灯光，常带站点水印、时间戳或源画面自带的灰边；国内公开机位大多是道路、广场、机场，纯自然风景机位很少。所以它做成可随时开关的模式，而不是直接替换你已经确认过的开阔湿地底图。

**来源与授权边界（本机实测）**：

| 来源 | 结果 |
| --- | --- |
| [opencam.live](https://opencam.live/) | **采用**。聚合道路 / 气象 / 景区运营方自行公开的摄像头，站点声明「无需注册、不留存、只转发实时画面」；公开帧接口可直接取 JPEG，地区页同时给出坐标与名称，已固化成本地静态索引。 |
| 央视网「[直播中国](https://livechina.cctv.com/)」 | 尝试过未采用。风景慢直播的 HLS 落在 `gcalic.v.myalicdn.com`，CDN 返回 `denied by IP ACL = not in whitelist`；同体系 `gctxyc.liveplay.myqcloud.com` 只给得出 master playlist，媒体分片连接超时，拿不到可播放画面。 |
| EarthCam | **未采用**。官方 FAQ 明确「未经许可不得转播直播流」「App / 网站内嵌需另行授权」，且本机连 `videos-3.earthcam.com` 超时。 |
| Port of Cams | 未采用。页面主要嵌入 YouTube Live，国内网络不可达；站点另有 Premium 付费层。 |

实时帧版权归各摄像头运营方，App 只在本机显示、不录像、不二次分发；索引来源与抓取时间记在 `Resources/图片来源.txt` 末尾。关闭开关后**不会发出任何取帧请求**。索引是抓取时的静态快照，个别摄像头可能下线，已由「候选自动切换 + 静态回退」兜住。

想直接以某个效果启动（调试用）：

```bash
open "天气桌面.app" --args --demo=sunset   # clear / sunset / rain / storm / snow / fog / night
open "天气桌面.app" --args --live          # 临时开启实时摄像头（不写入偏好）
open "天气桌面.app" --args --cam=<id>      # 固定某个公开摄像头
open "天气桌面.app" --args --biome=desert  # 强制某个生态带照片包
```

首次切到「精确定位」时系统会询问定位权限；只用 IP 定位或手动城市则不需要任何授权。

## 从源码构建

```bash
cd WeatherDesk
chmod +x build.sh
./build.sh             # 生成 ../天气桌面.app
./build.sh --verify    # 构建并跑 75 项自检（天气码、日出日落、星历、配色、素材包、摄像头索引、联网冒烟）
./build.sh --preview   # 生成 ../天气桌面-效果预览.png（九格：天气效果 + 真实星空 + 星图标注）
```

需要 Xcode Command Line Tools（Swift 5.9+，macOS 13 SDK）。`build.sh` 会生成图标、**优先用本机 Apple Development 开发者证书签名**（找不到才回退 ad-hoc），并清除隔离属性。固定签名身份可避免 TCC 权限与 `SMAppService` 登录项因每次编译身份变化而失效。`--preview` 会单独编译一个离屏渲染工具，把动画按各自相位定格后截图，用于校对渲染效果，不影响正在运行的 App。

## 安装与 Gatekeeper

App 未做 Apple 公证（需要付费开发者账号），`spctl -a` 会显示 `rejected`，这是签名策略而非文件损坏。本机直接双击 `/Applications` 里的 App 不受影响；**从网络下载/解压 zip 后若提示「已损坏，无法打开」**，先清掉隔离属性：

```bash
xattr -cr "/Applications/天气桌面.app"
```

重装或换签名后，如果用户此前开启过「开机启动」，App 会在启动时自动重新注册 `SMAppService` 登录项，不需要手动去系统设置里补。

## 数据与隐私

- 天气来自 [Open-Meteo](https://open-meteo.com/)（免费、无需 Key），定位来自 `ipwho.is`，备用 `ipinfo.io`，城市检索来自 Open-Meteo Geocoding API。
- 星表在编译时内置于 App，运行时**不联网请求任何天文数据**；天文位置全部由本机时间、经纬度与内置星表算出。
- 静态底图随 App 打包或放在本机 `scenes/` 目录，运行时不下载、不拼接、不生成任何图片，不依赖第三方图库或 AI 图像服务；12 张时段底图是离线预生成的普通 JPEG，App 只读文件。内置照片取自 Wikimedia Commons，署名、许可与改编说明见 `Resources/图片来源.txt`；可选的生态绘制同样在本机完成。
- 开启「实时摄像头」后，会定时向 `opencam.live` 的公开帧接口发 GET 取一张 JPEG（默认每 20 秒，约 20–200 KB）；请求里只有摄像头 ID，**不携带定位、天气或任何个人信息**，最近一帧也只缓存在本机。关闭开关即完全不请求。
- 天气 / 定位请求只带「经纬度 + 当前天气字段」；不上传截图、不上传文件、无账号、无埋点。
- 偏好与上次定位存在 `UserDefaults`（`com.xi.weatherdesk`），不写任何外部配置文件。
- 需要联网；离线时保持最后一次的天气画面，恢复后自动刷新。

## 已知限制

- macOS 不允许第三方程序修改「系统设置里的桌面图片」，所以本 App 是在**壁纸层之上、桌面图标之下**叠一块透明动态画布，效果等同动态壁纸，但不会改变系统壁纸文件本身。
- 全屏 App 与多 Space 下由 `.canJoinAllSpaces` 保证可见；极少数全屏游戏可能覆盖桌面层。
- IP 定位精度一般到城市级，且受 VPN / 代理影响；需要更准就切到「精确定位」或手动选城市。
- 天气接口的观测值本身有 15 分钟左右延迟；日出日落与时钟推进是本机连续计算的。
- 星空是一扇朝南（南半球朝北）的虚拟窗口，不是全天鱼眼：窗外看不到的星座不会出现在画面里，这是有意的。城市光污染按固定经验值估算，实际郊区 / 市中心的极限目视星等会有差异。
- 装了 Bartender / Hidden Bar 之类菜单栏管理器时，新状态项可能被自动折叠；多屏环境下 macOS 也可能把图标放到另一块屏幕的菜单栏。按 `⌃⌥W` 可直接在鼠标处呼出同一份菜单，是最可靠的入口。
- 实时摄像头是「每 15~20 秒一帧的快照」而非连续视频；画质取决于摄像头运营方，夜间常偏暗并带站点水印 / 时间戳。国内公开机位以道路、广场、机场为主，暂无稳定的纯自然风景慢直播源（央视「直播中国」CDN 有 IP 白名单，EarthCam 条款禁止未授权转播）。因此该模式默认关闭。
- 摄像头索引是抓取时的静态快照，个别机位可能下线；已用「依次尝试附近候选 → 回退静态照片 → 60 秒重试」处理，不会黑屏。
- IP 定位返回的城市名通常是英文（例如 `Tianjin`）；切到「手动指定城市」可以用中文名搜索。
